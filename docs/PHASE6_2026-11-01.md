# Phase 6: frozen-feature cache and gated student experiments

This page describes the code and reproducible workflow. Dataset-specific results,
per-frame reports, predictions and checkpoints are separate private artifacts.
The Android application still imports minimap models only.

## Frozen FP32 feature cache

`FeatureCache` is for an evaluation-mode, frozen encoder. Entries are bound to
encoder SHA, Torch version and exact input tensor hash/shape/dtype. The payload
has a content checksum; invalid, non-finite or trainable features are rejected.
Writes use a unique temporary file and atomic replacement. The runner checks a
cache reload against a live encoder forward. Cache precision remains FP32.

`heatmap_pose --feature-cache LOCAL_CACHE` reuses entries between matched runs.
Do not use frozen features when training the encoder or changing BatchNorm state.

## Train-only teacher proposals

`teacher_proposals` checks train paths, source-image hashes, reviewed-reference
provenance and holdout pixel duplicates. It compares predictions under a fixed
geometric/photometric perturbation after aligning coordinates back to the source.
It also requires confidence, reference-homography consensus and pitch-line support.
Automatic proposals remain experimental labels, never certified ground truth.

`--reuse-predictions` verifies the review, geometry, weight and transformation
hashes before avoiding repeated teacher inference. `--junctions-only` excludes
unresolved circle/spot semantics. Equal keypoint counts do not establish identical
ID meanings across datasets; inspect each schema before using world coordinates.

`heatmap_pose --teacher-unlabeled` keeps base targets on proposal images unknown.
Only accepted teacher points receive additional loss. Unknown points receive no
coordinate or negative-visibility gradient. An empty teacher treatment is rejected.
The original reviewed labels are not overwritten.

## Matched experiments and the no-regression gate

Use identical initialization, encoder, dataset, seed, augmentation, batch and step
budgets for a zero-teacher control and a bounded nonzero-teacher treatment. Keep
all original labeled training images. Validation does not choose optimizer steps
or early-stop checkpoints; a reused source validation remains exploratory.

`student_gate` checks those comparison contracts and the augmented image hashes.
It requires PCK5 and coverage not to decrease and coordinate median/P95 not to
increase against both the retained baseline and control. Coordinate predictions
cannot be dropped to improve tail-error statistics. The decision never authorizes
an Android release or certifies independent Mobile accuracy.

## Dense student ONNX export

`export_dense_student` exports the retained backbone/FPN and dense landmark head,
omitting the unused original YOLO pose head. Local soft argmax is in the graph.
Input: RGB FP32 `[1,3,320,320]`, range 0–1, direct resize. Output: `[1,32,3]`
coordinates/confidence in a 640-reference space. Scale x by original width/640
and y by original height/640. The exporter compares features, complete predictions
and fixed-threshold metrics against the original PyTorch path before passing.

Profile `dense_landmarks32_research` is not an Android minimap import bundle. It
has no scene/menu detector; capture integration, continuous video validation and
device performance measurement are separate work. A faithful export does not
establish the accuracy of the underlying checkpoint.
