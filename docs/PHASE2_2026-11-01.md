# Field and pitch-landmark research — 2026-11-01

Status: both bounded experiments and source-split evaluations are complete.
Player detection shows a useful research baseline; **ball and landmark quality
are insufficient for tactical guidance**. No Android field/pose integration or
independent Mobile acceptance is claimed.

The previous temporary training environment was lost before its later field/pose
checkpoints were saved. Those jobs cannot honestly be resumed. This recovery run
restored 5,246 files without download errors, matched the original dataset
fingerprints, and starts from official pretrained weights. The earlier minimap
baseline is retained separately and was not retrained.

## Field result

FP32 YOLO11n, 640 pixels, batch 16, AdamW 0.001, seed 20261030, four CPU threads,
oneDNN. **1/20 epochs actually completed in 832.65 seconds**. The 20-minute
budget stops at the saved boundary because another full epoch is estimated not
to fit. An earlier setup-only attempt was interrupted when optional label
plotting stalled; it completed zero epochs. The numeric run disables those plots
and starts from the same converted official pretrained weights. The loader
removes six duplicate training annotations; source files are preserved.

AP is not a percentage of all 22 players correctly read in a match. The test uses
the original source split, whose presumed source groups overlap training; it is
not independent by match/video or Mobile device. No test result was used to
select or retune this checkpoint. Four fixed-threshold source previews show
missed balls and extra/misclassified detections; they are diagnostic examples.

At input side 640, the source training ball boxes have median size 5.5×10 pixels;
18.55% have a shortest side at most four pixels. There are 2,151 raw ball label
rows versus 34,155 player rows. These measurements identify a small-object
challenge; they do not prove the sole cause of low ball AP. Square source exports
also require aspect-ratio/domain verification before Android deployment.

The field ONNX is `[1,11,8400]`. PyTorch/ONNX parity passes on three validation
images (maximum absolute raw-output difference 0.0014343). Best and last are
byte-identical after this one-epoch run. Full metrics, checksummed checkpoints,
preview images and private source restoration manifests are delivered separately.

## Landmark result

FP32 YOLO11n-pose, 640 pixels, batch 4, AdamW 0.001, seed 20261030, four CPU
threads, oneDNN. Train sigma 0.1; upstream validation OKS sigmas unchanged.
Geometric augmentation is disabled. Budget: 12 minutes; **15/80 epochs actually
completed in 679.76 seconds**, then saved-boundary stopping. Requested epochs
must not be reported as completed epochs.

| Checkpoint | PCK@5 px | PCK@10 px | Median error | P95 error |
| --- | ---: | ---: | ---: | ---: |
| Upstream best, epoch 10 | 0/92 | 0/92 | 143.53 px | 371.21 px |
| Last, epoch 15 | 0/92 | 0/92 | 140.87 px | 253.64 px |

These are original source-image pixels, scoring visibility-2 ground truth. Both
confidence-filtered and unfiltered PCK are zero. Missing detections count as
misses. Last is retained as the research candidate using the predeclared
validation-only tie-breaker; **neither checkpoint passes acceptance**.

Pitch-box mAP50 is 99.5%, while pose mAP50 is zero. The box score does not show
that the network locates pitch landmarks. The run does not establish whether the
remaining failure is training budget, loss/optimization, or additional label
inconsistency. Before a long GPU run, use a small training-only overfit check
with pixel PCK and visual target checks; then evaluate untouched validation.

Both checkpoints export to FP32 ONNX `[1,101,8400]`. Python CPU raw-output parity
passes on three validation images. Device Bitmap/ARM parity, latency, sustained
game FPS and thermal behavior remain unmeasured. The current APK imports only
the minimap model. `modelsValidated=false` and calibrated field guidance stays
disabled.
