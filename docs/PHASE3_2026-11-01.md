# Pose optimization diagnostics and candidate source splits

The network can memorize reviewed training images, but **held-out source
coordinates still fail**. None of these experimental weights replaces the
phase-2 application/research baseline. Android still connects minimap only;
field guidance and calibrated AR remain disabled.

## Measured results

Pixel PCK uses visibility-2 ground truth, score 0.5, pitch score 0.25 and pitch
box IoU 0.5. Missed objects/points remain misses. Pixel thresholds did not change
between experiments. Train memorization and source validation are separate.

| Experiment | Scored data | PCK@5 px | PCK@10 px | Median error |
| --- | --- | ---: | ---: | ---: |
| Phase-2 last checkpoint | 10 source validation images, 92 points | 0/92 | 0/92 | 140.87 px |
| One-image memorization, 200 + 60 updates | 1 train image, 9 points | 9/9 | 9/9 | 0.47 px |
| Eight-image full-network control, 600 updates | 8 train images, 82 points | 0/82 | 0/82 | 36.84 px on 56 object-matched points |
| Eight-image full-network control with fixed BN, 600 updates | Same 8 train images | 0/82 | 0/82 | unavailable: no pitch matches |
| Pose-head-only cached training, 600 + 600 + 30 updates | Same 8 train images | 81/82 | 82/82 | 1.48 px |
| That eight-image model on source validation | 10 source validation images, 92 points | 0/92 | 2/92 | 156.28 px |
| Full 93-image pose-head experiment, 2,096 updates | 93 train images, 928 points | 46/928 | 162/928 | 23.24 px |
| That full-source model on source validation | Same 10 source validation images | 0/92 | 2/92 | 98.35 px |

The full-source model's validation P95 error is 270.95 px, versus 253.64 px for
phase 2. A lower median alone does not satisfy acceptance. Full-source training
PCK also remains low; this is not evidence that generalization alone is the
remaining problem. No validation result was used to choose among further models
after this full-source run. Source groups are not independently verified by
match/video, and no new Mobile/device accuracy is claimed.

## What the controls establish

- The 15-epoch phase-2 checkpoint contains only **31 AdamW/EMA updates**, confirmed
  from both optimizer state and EMA count. Epochs cannot substitute for update
  counts when nominal batch size causes accumulation. The main runner now records
  those counts and exposes nbs with the existing default 64.
- No-augmentation image tensors match Ultralytics preprocessing exactly on the
  eight chosen training images. Bbox/keypoint differences are below 1e-6.
  The new PyTorch pixel evaluator agrees with the previous ONNX evaluator on the
  unchanged baseline: PCK identical, median error difference 0.0000207 px.
- BatchNorm affects tiny-batch evaluation. For the failed eight-image control,
  per-image batch statistics reduce matched-point median error from 36.84 to
  5.07 px, but simply fixing statistics while training all parameters still
  fails. Using training statistics at live inference is not the adopted fix.
- Freezing the backbone and bbox branch, fixing BN moments and learning cv4
  alone is stable on the tiny subset. For 600 updates, optimization/probing takes
  77.19 s versus 316.52 s for the full-network control. These train different
  parameter subsets; this is not an equivalent full-network speed claim.
  Caching accelerates training only. Live inference still computes the backbone.
- Cached/full-network outputs match exactly before and after optimization.
  Frozen weights are checksum-identical and BN buffer change is zero. The
  eight-image final model has 82 visibility true positives, one false positive,
  no false negatives and 173 true negatives against the same training labels.
  IDs 5 and 29 are absent from this subset; it does not test all 32 IDs.

The full-source experiment starts from the original phase-2 last checkpoint,
not the eight-image overfit weights. It uses all 93 training images, 2 CPU
threads, no augmentation, microbatch 1, one optimizer update per step, and only
cv4 trainable. Training sigma is 0.1/LR 0.001, then 1/32/LR 0.0001 after update
1,600. It stops at **2,096/2,400 requested updates** by the five-minute training
budget: 304.10 s including final probing, plus 31.32 s preparing/verifying the
feature cache. Cache size is 266,649,600 bytes. Time is measured here, not an
Android inference/FPS benchmark.

No raw files are moved. Exact-pixel-linked groups stay together; a known group
sharing pixels with an unknown source is quarantined. Source identities and
class balance remain unverified, so the plan is **not training-ready or an
independence certificate**. Do not resume the phase-2 field weights for this
new holdout: they have already seen potential holdout images. Use fresh official
pretrained initialization after reviewing the split.

## Deliverables and next gate

The private package retains every completed run, including failed controls,
step histories, checkpoints, target selections, source validation images and
the complete 103-image reviewed pose dataset with label correction provenance.
Repository code contains no user images or Drive IDs. The weights remain
debug/non-release. The ordinary run exporter rejects debug weights rather than
copying unrelated epoch metadata into their manifest.

Sixty-four Python tests pass locally. The PR links the final CI run for Python,
Kotlin core tests, Android lint and APK assembly. Next work must improve fitting
and held-out coordinates with sufficient optimization, suitable batches/backbone
adaptation, and verified labels/source groups. Preserve the fixed evaluation
criteria; do not enable tactical advice based on memorization scores.
